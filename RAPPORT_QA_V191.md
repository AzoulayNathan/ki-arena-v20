# KI ARENA V19.1 — fin de run, Panthéon, impacts

Une défaite clôt désormais immédiatement l’aventure, même si des réservistes restent vivants. L’équipe enregistrée est l’effectif exact du dernier affrontement, avec ses actifs, réservistes, niveaux, équipements et états après combat. Aucun soin, XP, récompense ou nouveau combat ne suit cette défaite. La résolution répétée est refusée. L’identifiant du souvenir est propre à la run, pour éviter l’écrasement entre deux runs de même seed.

Le bilan affiche les statistiques infligées/subies/soignées en clair ; le premier onglet contenant des contributions est ouvert. La victoire présente également les trois contributions du dernier combat avant les choix de récompense. Le Panthéon reprend les cadres de cartes et les badges K.O./Réserve, avec un décor sobre et une entrée brève, désactivée en mouvement réduit.

Les attaques ajoutent un déplacement court de l’attaquant, une réaction de la cible, une trajectoire pour les attaques d’énergie, un noyau lumineux pour les rayons et un impact local. Soin et bouclier ont des halos distincts. Un K.O. produit une vignette brève, une secousse de deux pixels et un son grave synthétique court. Le son respecte mute et le volume d’effets. Les animations sont raccourcies en vitesse accélérée et les effets ajoutés sont supprimés en mouvement réduit. Ils ne modifient aucun résultat de combat ni RNG de simulation.

Preuves : qa/v191/rule-proof.json, browser.json et effects.json. Le parcours de défaite utilise un véritable combat contre un boss d’un acte ultérieur délibérément sélectionné dans une fixture, et six personnages du catalogue. Le test vérifie la défaite malgré une réserve vivante, les six IDs exacts du souvenir, le refus de double résolution, l’export/import et la persistance du Panthéon après rechargement. Captures réelles en 390, 768 et 1360 px. Les hooks d’effets sont aussi exercés isolément (rayon, soin, bouclier, K.O., nettoyage, mute, mouvement réduit), sans altération de l’état simulé. Les assertions sortent en code non nul sur échec.

`npm test` conserve les suites V8, les protections V18, les 92 tests modernes, les 11 tests V19 et les contrôles d’objets. Les anciens fichiers de données, illustrations, templates et moteurs historiques sont inchangés. Les anciennes captures et recettes de qa/v19 sont les preuves de la V19 de base ; les preuves actuelles de cette modification sont dans qa/v191. L’ancien vérificateur V19 signale normalement les preuves devenues périmées : utiliser scripts/package_v191.py pour ce correctif.

**IMAGES : BLOCKED / INCOMPLET.** Les nouveaux cadres et les branchements fonctionnent, mais cela ne termine pas la bibliothèque canonique. Une étude de Goku est intégrée, les 599 autres portraits DB sont encore les SVG génériques hérités et les 2 422 portraits des autres mangas manquent. Les objets gardent les illustrations adaptées/de catégorie ou pictogrammes identifiés. Aucun nouveau lot complet d’images réelles n’a été récupéré dans cette modification. Le contrôle d’accès à une source externe est consigné dans image-source-probe.json. Le jeu n’est pas annoncé « fini avec toutes les images ».

**Autres limites maintenues :** difficulté des boss non recalibrée ; le résultat 0/1000 actes franchis concerne l’ancienne simulation V19, pas une nouvelle certification de V19.1. Windows natif et les douze tests Python de référence restent non validés. Jeu autonome vérifié sous Chromium/Linux. Les images et les sons déjà inclus sont locaux ; aucune connexion n’est requise pour jouer.

## Packs et collection personnelle

Un pack de trois personnages est enregistré automatiquement au bilan d’une run terminée avec au moins une victoire, y compris après une défaite ultérieure ou un repli volontaire. Une défaite immédiate sans victoire ne donne pas de pack. Chaque run a un identifiant de récompense unique ; réafficher/recharger le bilan ne redonne ni carte ni doublon supplémentaire. Les tirages ont leur flux cosmétique séparé et n’altèrent pas le RNG des combats.

Les cartes proviennent uniquement des mangas sélectionnés dans la run. Raretés : Commune 33 %, Peu commune 27 %, Rare 21 %, Épique 15 %, Légendaire 4 %. Finitions : Noire 45 %, Blanche 45 %, Dorée 10 %, indépendantes de la rareté. Les duplicatas d’un même personnage/finition sont comptés. Les trois cartes sont inspectables avec leur propre finition.

La nouvelle collection personnelle possède une recherche par personnage/forme/technique, les filtres historiques de manga/rareté/effet, un filtre de finition et le choix Mes cartes / Catalogue. Elle est sauvegardée dans ce navigateur, séparément des sauvegardes historiques et du catalogue. Les anciennes possessions des modes V8 restent dans ces modes : aucune conversion automatique n’est annoncée. L’export d’une run ne constitue pas une sauvegarde de cette nouvelle collection personnelle.

Preuves : tests/test-packs-v191.mjs (1 000 packs, univers, finitions, raretés, idempotence, condition de victoire) et qa/v191/packs-browser.json (gain réel, affichage des trois cartes, filtre de finition, recherche, rechargement, 390/1360 px). Les autres recettes V19 de base restent archivées ; le changement du choix par défaut vers Mes cartes remplace volontairement l’ancien catalogue affiché d’emblée.

L’accès créateur est conservé dans Réglages → Accès créateur, code **N**. Il n’augmente aucune probabilité. Les nouveaux packs ne fournissent pas de nouveaux portraits : ils utilisent les illustrations locales effectivement disponibles et leurs replis identifiés.
